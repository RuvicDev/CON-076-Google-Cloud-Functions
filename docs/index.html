¿Qué es y para qué sirve?

Este conector permite al agente de Ruvic invocar una función HTTP de Google Cloud Functions con un payload, listar las funciones desplegadas en la región configurada, y consultar el estado de despliegue de la función configurada.

Este conector ejecuta código real invoke ejecuta la función real configurada, que puede tener efectos secundarios (escribir en otros sistemas). list_functions y get_status son de solo lectura.
OperaciónQué hace
cloud_functions.invokeInvoca la función HTTP configurada con un payload
cloud_functions.list_functionsLista las funciones desplegadas en la región
cloud_functions.get_statusConsulta el estado de despliegue de la función configurada

Prerrequisitos

  • Una función de Google Cloud Functions (2nd gen) ya desplegada con trigger HTTP.
  • Acceso a Google Cloud Console para crear una cuenta de servicio.

Configuración en el fabricante

  1. Creá una cuenta de servicio dedicada.

    En Google Cloud Console → IAM y administración → Cuentas de servicio → Crear cuenta de servicio. Generá y descargá una clave JSON.

  2. Otorgá acceso con mínimo privilegio.

    Asigná los roles "Cloud Functions Viewer" (listar/consultar estado) y "Cloud Functions Invoker" (invocar), idealmente limitados a la función específica.

  3. Anotá los datos necesarios.

    El contenido completo del archivo JSON de la cuenta de servicio, la región y el nombre de la función.

Permisos requeridos

PermisoPara qué sirve
Cloud Functions ViewerListar funciones y consultar estado de despliegue
Cloud Functions InvokerInvocar la función configurada
Nota No se otorga el rol "Cloud Functions Admin", que permitiría desplegar, modificar o eliminar funciones.

Configuración en Ruvic

Entrá a Settings → Conectores, buscá Google Cloud Functions y pulsá Configurar. Pegá el JSON de la cuenta de servicio y completá región y nombre de función.

Probar conexión — la plataforma consultará el estado de la función para confirmar credenciales.

Verificación

  1. Test de conexión exitoso.

    "Probar conexión" debe responder con éxito.

  2. Prueba mínima con el agente.

    Pedile:

    "Listame las funciones desplegadas en esta región."

    El agente debe devolver el listado real de funciones y sus estados.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Credenciales inválidas o sin permiso IAM suficiente"Falta el rol "Cloud Functions Viewer" o "Cloud Functions Invoker", o la clave fue revocada.
"La función no existe"Nombre de función o región mal escritos, o la función está en otro proyecto distinto al de la cuenta de servicio.
"La función no tiene una URL HTTPS invocable"La función usa un trigger de eventos (Pub/Sub, Storage, etc.) en vez de HTTP; invoke solo funciona con funciones HTTP.
"Sin permiso para invocar la función" (401/403 al invocar)Falta el rol "Cloud Functions Invoker" específicamente sobre esa función, o la función no permite invocaciones no autenticadas ni de esta cuenta de servicio.

Preguntas frecuentes y notas de seguridad

¿El agente puede desplegar o modificar funciones?

No. La cuenta de servicio solo tiene permisos de lectura e invocación; el conector no expone ninguna operación de despliegue.

¿Dónde queda guardado el JSON de la cuenta de servicio?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

Rotación de credenciales

Generá una nueva clave para la cuenta de servicio periódicamente desde Google Cloud Console y actualizala en el formulario; luego eliminá la clave anterior.

¿Qué hago si el JSON de la cuenta de servicio se compromete?

  1. Eliminá la clave comprometida en Google Cloud Console → IAM y administración → Cuentas de servicio.
  2. Generá una nueva clave y actualizala en el formulario.
  3. Revisá los Cloud Audit Logs por invocaciones inesperadas de la función.
Buenas prácticas Usá una cuenta de servicio dedicada con acceso limitado a la función específica; nunca uses una identidad con el rol Cloud Functions Admin; y confirmá con el usuario antes de invocar una función de producción.
